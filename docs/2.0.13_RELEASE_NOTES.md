# Website Core 2.0.13

## Core Updates recovery

The Updates screen now uses its own `UpdatesController`. Opening the screen
does not instantiate an archive inspector or parse `staged-update.zip`.
Instead, a successful explicit upload writes a compact private review record;
the GET screen reads only that bounded metadata and a bounded journal tail.
Applying an update still repeats the full archive, signature, integrity,
backup, and migration workflow before changing live files.

An abandoned staged ZIP without a review record produces an administrator
warning asking for a replacement upload. It cannot crash the GET screen.

## Server-level 500 page

Core now includes a standalone branded `errors/500.html` that requires no PHP,
database, JavaScript, or external network asset. Bootstrap maintains an
Apache/LiteSpeed `ErrorDocument 500` directive with the installation's actual
subfolder path. Errors that occur before the application exception handler can
start therefore receive a useful designed recovery page instead of the
browser's generic HTTP 500 screen.

## Deployment

Extract the matching `REPAIR-UPLOAD` archive into the installed site's root
and overwrite existing files. Configuration, storage, uploads, and installed
module state remain excluded.
