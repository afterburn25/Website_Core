# Website Core 2.0.14

Version 2.0.14 is a commercial presentation and usability release. It does not
add a new product area. It makes the administration functions already in Core
feel consistent, safer, and more complete.

## Administration workspace

- Collapse the desktop sidebar when more editing room is useful. Core keeps
  the choice and preserves the separately saved open/closed category state.
- Choose compact spacing from the administrator account menu. The preference
  remains local to that browser and does not affect other administrators.
- Destructive actions now use one branded accessible confirmation dialog.
- Large forms warn before unsaved work is abandoned, limited text fields show
  live character counts, and brand uploads preview before saving.

## Consistent state controls

Maintenance mode, mandatory MFA, form availability, the consent banner,
webhooks, administrator access, and installed-module state now use the same
keyboard-accessible on/off switch language. Dangerous switches retain an
explicit confirmation and return to their prior position when canceled.

## Settings safety

Settings hide or disable fields that do not apply to the selected mail or
analytics provider. Switching away from SMTP preserves the stored server and
credential values, so temporarily using PHP mail or disabling delivery cannot
silently destroy a known working configuration.

## Upgrade

Upload the 2.0.14 repair/update package over the installation or apply the
official Core update through **System → Core updates**. Configuration, storage,
uploads, themes, and industry-module data are not replaced.

## Health, Audit, and fatal recovery

System Health and Audit now run from separate fail-safe controllers. Health
collectors fail independently, while an Audit query failure renders a usable
workspace and recovery warning. Neither screen should become another HTTP 500
while reporting an underlying problem.

Core also registers a minimal shutdown renderer in `index.php` before cleanup
or bootstrap code loads. Fatal PHP failures reached through the front
controller directly render the bundled branded 500 design with root- or
subfolder-correct asset, retry, and administrator-login URLs. This covers
shared hosts that ignore Core's dynamic `.htaccess` ErrorDocument mapping.
