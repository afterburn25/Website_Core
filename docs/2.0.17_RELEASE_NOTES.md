# Website Core 2.0.17

Version 2.0.17 completes the Forms and Submissions workspace's
commercial-polish pass. It stays inside Core's basic reusable intake boundary:
focused website forms, secure storage, notifications, consent evidence, and an
administrator inbox. Conditional logic, multi-step campaigns, CRM automation,
payments, and other advanced form products remain package territory.

## Forms workspace

- Build fields in a guided responsive workspace with a representative public
  preview.
- Drag fields into order or use the labeled up/down controls without a pointer.
- Configure labels, stable export names, field types, required state,
  placeholders, help text, autocomplete purpose, and dropdown choices.
- Receive actionable validation for duplicate identifiers, missing choices,
  excessive lengths, missing forms, and invalid definitions.
- Keep all entered settings and fields visible after a failed save.
- Pause and reactivate a form without deleting its settings or response
  history.

## Submission inbox

- Filter by text, form, and processing state with status summaries and
  pagination.
- Expand an entry to see every submitted value, recorded checkbox consent, and
  the linked notification queue state.
- Select a page of entries and mark them new, read, archived, or permanently
  delete them through guarded bulk actions.
- Export the filtered response set as useful columns instead of a raw JSON
  cell. Consent and notification evidence are included, and spreadsheet
  formula prefixes are neutralized.

## Public intake and notifications

- Stored dropdown choices and calendar dates are validated server-side.
- Checkbox evidence records whether and when consent was accepted.
- Queued notification messages retain a traceable connection to their source
  submission.
- Successful and invalid submissions use the shared branded, no-store response
  presentation.
- Existing CSRF, honeypot, bounded-value, and IP-scoped throttling protections
  remain enforced.
- Site transfer carries form definitions and remaps page Form blocks while
  excluding recipient addresses and every submitted response.

## Upgrade

Migration `2026_10_25_0025` adds a submit-button label to forms and
notification/update metadata to submissions. Existing forms default to
**Submit**, and existing submissions remain unchanged.

Upload the 2.0.17 repair package over an installed 2.x site or apply the
trusted update through Core Updates. The installed-site schema boot gate runs
the migration before the new Forms controllers query the added columns.
