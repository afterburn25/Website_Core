# Website Core 2.0.28

Released: 2026-10-24

## Industry-module contract completion

- Adds the root `MOD_RULES.md` creation/release checklist and aligns the
  detailed rules, Module API, package spec, schema, and repository contract.
- Makes duplicate IDs and package-directory type mismatches persistent
  discovery errors that database state cannot hide.
- Detects dependency cycles before enablement and quarantines an enabled
  dependent when a required dependency does not successfully boot.
- Confines entry, PSR-4, migration, asset, integrity, and starting-brand paths
  to the package; themes cannot declare executable PHP hooks or migrations.
- Requires declared entry paths, PSR-4 directories, and provider classes to
  exist and records a package-local failure instead of silently booting it.
- Validates admin routes/pages, contribution keys, capabilities, labels,
  dashboard/health duplicates, and default navigation destinations.
- Supports one or multiple declared migration directories consistently during
  package install, filesystem finalization, and bundled browser setup.
- Enforces exactly one enabled industry package while retaining independent
  reusable add-ons and themes.
- Updates native installer CI to exercise the claimed-session CSRF contract
  and advances direct repair-artifact checks to 2.0.28.

## Upgrade notes

No database migration is required. Existing valid modules continue to use API
v1. Invalid or ambiguous packages now remain isolated with actionable Module
Manager errors instead of partially booting.
