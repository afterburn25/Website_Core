# Website Core 2.0.29

Release candidate: 2026-10-25

## Hosted acceptance repair

- Fixes backup creation on MySQL and MariaDB when PDO native prepares are
  enabled. Those servers reject placeholders in `SHOW TABLES LIKE ?`.
- Discovers prefixed tables through `information_schema.tables` with bound
  values, literal prefix semantics, and deterministic ordering.
- Adds a native database regression test that migrates the schema, creates a
  real ZIP recovery point, validates its manifest, and confirms Core tables
  are included on both MySQL and MariaDB CI services.
- Removes hard-coded prior-version paths from repair-artifact staging and
  derives uploaded artifact names from the running Core version.

## Hosted acceptance status

The packaged 2.0.28 `/catering/` installation passed major Core and Catering
admin-screen smoke tests, public content and image checks, maintenance/login,
the no-rewrite custom 404, contact handling, quote review, keyboard entry, and
admin navigation-state persistence. The backup defect above blocked safe
restore, update rollback, and destructive module lifecycle testing.

Direct unknown paths on the tested nginx host still return its plain
`File not found.` response before PHP. The supported no-rewrite form,
`index.php?p=/missing-path`, reaches Core and renders the branded 404. A host
rewrite/error-page rule is required if clean URLs must use Core error pages on
nginx.

## Upgrade notes

No database migration or module API change is required. Upload the 2.0.29
Core repair/update artifact through the existing update workflow. Create and
verify a new recovery point before attempting restore, rollback, package
uninstall, purge, or quarantine acceptance.
