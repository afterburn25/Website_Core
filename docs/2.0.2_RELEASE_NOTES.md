# Website Core 2.0.2

## Commercial hardening, not feature expansion

Website Core 2.0.2 freezes broad feature development and starts a systematic
commercial-readiness pass. `docs/COMMERCIAL_HARDENING.md` lists every existing
surface in the order it will be completed and defines the evidence required
before a surface can be marked verified.

Each pass now covers real functionality and recovery—not just whether a screen
renders—plus validation, permissions, security, empty/error/success states,
responsive GUI polish, accessibility, native database tests, packaged-hosting
behavior, and documentation.

## Administration shell and dashboard

The first hardening pass rebuilds the UI shared by every Core and industry
administration page:

- Versioned Core CSS and JavaScript replace the large embedded layout styles.
- Assets use the constrained `/_a/core/*` resolver and work without rewrite
  rules in root-domain and subfolder installs.
- Desktop navigation preserves category state and sidebar scroll position.
- Mobile navigation provides labeled open/close controls, an overlay, Escape
  handling, focus transfer, and reduced-motion behavior.
- The sticky header presents section/page hierarchy, global search,
  notifications, public-site launch, and administrator account actions.
- Alerts are announced to assistive technology and can be dismissed.
- Cards, metrics, forms, tables, buttons, badges, builders, focus states, and
  responsive breakpoints share one polished design system.
- Dashboard metrics and quick actions now lead directly to real existing
  management workflows.

There is no database migration and no Module API change in 2.0.2. Catering
0.1.16 remains compatible because its declared range includes Core 2.0.2.
