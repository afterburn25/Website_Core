# Website Core 2.0.3

## Commercial hardening: Content and Page Editor

Website Core 2.0.3 completes the code pass for the second surface in the
commercial-hardening program. This release improves existing content
workflows; it does not add an unrelated product area or change Module API v1.

### Safer page lifecycle

- Optimistic locking prevents a stale editor tab from silently overwriting a
  newer saved version.
- Revision snapshots now contain all editable page fields, not only the title
  and body, and restoring a revision first preserves the current page.
- Invalid canonical URLs, schema JSON, parent pages, sharing images, and
  publishing dates produce actionable errors instead of being discarded.
- Missing and deleted records return 404 for lifecycle actions.
- Permanent deletion is limited to already-trashed pages, is confirmed in the
  interface, is audited, and cleans related revisions, preview tokens,
  translations, and page-linked menu items.

### Polished content workspace

- The list includes status summaries, search, filters, pagination, scheduled
  state, useful empty states, direct site links, and compact secondary actions.
- GET filters explicitly carry the `p=/admin/pages` route, so they work on
  shared hosts and subfolder installs without rewrite rules.
- The editor uses a responsive content/sidebar workspace with clearer status,
  parent-page and public-social-image selectors, live search preview,
  character counts, and content-quality guidance.
- The block composer keeps drag ordering and adds labeled keyboard controls,
  accessible announcements, boundary states, and removal confirmation.
- Unsaved-change protection warns before accidental navigation.
- Draft Preview opens the actual tokenized preview in a new tab.

Migration `2026_10_23_0022` adds `pages.lock_version` and
`page_revisions.snapshot_json`. Both columns are additive and existing
revisions remain restorable through the legacy fallback.
