# Website Core 2.0.5

## Core-owned branding with module defaults

Website Core 2.0.5 applies the proven navigation ownership model to branding.
An industry module may bundle a starting logo, favicon, or social image and
declare it with Module API v1. Core confines the path to the installed package,
validates the file through the Media pipeline, copies it into Core-owned
storage, records its usage, and imports it only when no administrator selection
already exists.

The seed marker is permanent. Repeated requests and module updates do not make
new copies, overwrite an administrator replacement, or repopulate an asset the
administrator intentionally cleared.

## Appearance and shared rendering

Website → Appearance now includes:

- direct logo and favicon uploads;
- current logo/favicon previews;
- the existing Media-library selectors and clear option;
- PNG, JPEG, WebP, GIF, and ICO validation through Core Media;
- the existing design-token and social-image controls; and
- a custom plain-text copyright notice with `{year}` and `{site_name}` tokens.

The current Core logo and favicon are used consistently by the base public
theme, shared administration shell, and compatible module layouts. Safe text
or mark fallbacks remain when no asset is selected.

Website → Navigation Menu now provides separate **Header menu** and **Footer
menu** tabs. Both locations use the complete visual tree editor, including
drag ordering, nesting, page lookup, external URLs, and same-tab/new-tab/new-
window targets. The selected location survives every action and each menu is
isolated at the service boundary.

The custom copyright is rendered by Core and compatible industry layouts. It
does not replace or modify the required Cajun Web Pro design-and-development
credit, which remains a separate immutable Core concern.

## Catering 0.1.18

The synchronized catering module includes the approved transparent generic
**CATERING CO.** logo. It declares that image as its starting logo, renders the
current Core-owned brand assets on public and administration pages, and
requires Core `>=2.0.5,<3.0.0` with Module API 1. It also declares a starting
footer menu, which Core imports once and then leaves entirely under
administrator control. Its footer renders that stored tree and the
Core-managed copyright notice instead of hard-coded links.

There is no database schema migration. Automated coverage verifies one-time
copying, source preservation, path confinement, clear-without-repopulation,
Appearance uploads, header/footer menu isolation, footer rendering, shared
admin wiring, and the installed catering package.
