# Website Core 2.0.6

## Commercial workflow and administration polish

Website Core 2.0.6 completes a cross-surface hardening pass without adding a
new product area. The work concentrates on existing controls: making them
clearer, safer, complete, responsive, auditable, and suitable for ordinary
business administrators.

### Administration experience

- Every Core destination now has a recognizable icon and a concise purpose
  statement in the shared shell.
- Navigation categories retain their state, show item counts, and remain
  accessible on mobile; tables, cards, forms, alerts, empty states, loading
  states, and confirmations share one presentation system.
- Public-site launch actions use the real installation base path, including
  subfolder and no-rewrite installations.

### Completed workflows

- Media adds visual browsing, search, pagination, folder/tag organization,
  bulk feedback, focal metadata, replacement, usage visibility, and auditing.
- Navigation keeps separate header/footer trees, clearer source and target
  choices, drag ordering, unsaved-change protection, validation, and auditing.
- Forms adds a guided field builder and a searchable, filterable, paginated
  submission inbox with new/read/archive transitions and filtered CSV export.
- Settings adds real mail transport choices and an immediate delivery test.
- Integrations adds webhook re-enable and failed-delivery retry controls.
- Audit history is searchable and paginated, while mutation coverage now
  includes SEO, translations, patterns, roles, privacy, integrations,
  packages, backups, operations, marketplace, agency, and settings.

### Recovery and release safety

Backups, operations, modules, health, updates, and installer recovery keep
their existing security boundaries while presenting clearer consequences,
status, recovery steps, and destructive confirmations. Core remains protected
and cannot be disabled or uninstalled. Industry packages continue to declare
their own admin group and starting navigation/brand assets, after which Core
owns the editable site state.

The complete PHP, database, package, artifact, and Core-only matrices are the
release gate. Packaged shared-host browser acceptance remains documented as
the final external validation step.
