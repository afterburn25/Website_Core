# Website Core 2.0.8

Released 2026-10-24.

## Shared-host module update recovery

- Module Manager compares each active package's on-disk manifest with its
  registered database manifest.
- A mismatch is displayed clearly with both versions and a **Finalize update**
  action. Finalizing validates compatibility, checks the package license when
  applicable, runs pending module migrations, synchronizes the database record,
  resets OPcache, and keeps the package enabled or disabled as it was.
- This provides a supported recovery path when a shared-host file manager is
  used to replace module files outside the normal ZIP staging workflow.

## Normal package upgrades

- Staging records the package state that existed before the upgrade.
- A successful upgrade restores `enabled` or `disabled` instead of always
  leaving the package merely installed.
- Stage records created by older Core releases remain readable.

## Deployment repair

If a previous Core upload was incomplete and `/admin/updates` is unavailable,
extract the matching `Website-Core-INDUSTRY-2.0.8-REPAIR-UPLOAD.zip` directly
into the installed site's web root. This archive combines the complete current
Core runtime with the industry files at the bundled installation directory
(`modules/industries/industry-INDUSTRY/`), while omitting installer entry files,
runtime `config.php`, storage data, and uploaded media. Open Module Manager
afterward and select **Finalize update** to run the industry migration and
synchronize its recorded version.
