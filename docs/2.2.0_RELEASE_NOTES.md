# Website Core 2.2.0

Core 2.2.0 reduces repeated industry-module code while preserving strict
module ownership of industry rules and records.

## Shared business profile

Website → Business profile now stores one business identity, legal name,
email, phone, website, address, service area, and hours. Modules may provide
blank-value defaults once through `businessProfile()`. Later boots and module
upgrades do not overwrite administrator changes.

## Reusable module administration

`ModuleContext::adminView()` renders a registered module view in the complete
Core administration shell and enforces the supplied capability.

`ModuleContext::adminResource()` provides a standard responsive list/editor
for ordinary module records. Modules declare allowlisted fields and columns
plus list, find, save, and optional delete callbacks. Core supplies capability
checks, CSRF, validation, filtering, pagination, confirmations, auditing,
errors, and empty states; storage and industry rules remain module-owned.

## Inquiries and quotations

Modules may opt into `crm.inquiries` and `crm.quotes` with
`leadManagement()`. Undeclared features remain absent from navigation and
return the branded unavailable page.

The inquiry workspace includes:

- package-scoped customer requests;
- optional Core form-submission linkage with retry deduplication;
- new, contacted, qualified, quoted, won, lost, and archived states;
- low, normal, high, and urgent priorities;
- administrator assignment; and
- private timestamped notes.

The quote workspace includes:

- itemized, server-calculated prices and totals;
- discount and tax amounts entered explicitly by staff;
- draft, sent, accepted, declined, expired, and cancelled states;
- optional expiry dates and public/customer notes; and
- a 48-character random response token stored only as a SHA-256 hash.

The plain customer link is shown once when a quote becomes sent. Acceptance
or decline invalidates that token. Core does not provide automated tax rules,
contracts, e-signature, payment collection, lead scoring, or industry pricing
formulas.

## Data lifecycle

Migration `2026_10_25_0030` adds `crm_inquiries`, `crm_inquiry_notes`,
`crm_quotes`, and `crm_quote_items`. Disabling or uninstalling a module hides
its Sales workspace and preserves its data. Explicit package purge removes
the package partition in dependency-safe order.

The Core API major remains 1 because these APIs are additive. Existing 2.1
modules remain compatible and do not expose Sales unless updated to opt in.

## SMTP diagnostics

The in-page SMTP connection test now verifies hostname resolution and raw TCP
reachability before the SMTP handshake. Failures distinguish a nonexistent
host, blocked/refused port, TLS or certificate mismatch, and rejected
credentials. The settings screen also explains that `mail.domain.com` is a
suggested default and should be replaced with the exact outgoing-mail hostname
from the hosting provider when it does not resolve or accept connections.
