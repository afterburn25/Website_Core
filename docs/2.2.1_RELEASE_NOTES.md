# AllWebPro Core 2.2.1

Settings → Transactional email now includes **Diagnose host and ports** for
cases where a TCP port answers but the encrypted SMTP greeting fails.

The diagnostic checks SSL/465 and STARTTLS/587 independently. When available,
it obtains the original address's reverse hostname, confirms that forward DNS
contains that same address, and tests the verified hostname against that
original address. Certificate and hostname checks remain enabled for every
probe. A successful result identifies a concrete host/encryption/port pair;
the administrator must still test mailbox authentication before saving it.

Discovery sends no authentication credentials or email and changes no saved
settings. The existing connection/authentication and delivery tests remain
separate. Results show individual host/port outcomes using text-only rendering
and fixed diagnostic messages without raw server responses.

Each network probe has a 1.5-second budget shared across connect, TLS, and SMTP
reads. At most four pairs are attempted within an eight-second orchestration
budget. Native DNS calls use the hosting operating system's resolver timeouts;
if DNS exhausts the budget, further probes are skipped. The browser retains
its existing 12-second request timeout. These bounds can produce an
inconclusive result on a slow host; they never trigger an insecure fallback.

No database migration, Module API change, or industry-module synchronization
is included. Core, Catering, and other modules retain their separate versions.
