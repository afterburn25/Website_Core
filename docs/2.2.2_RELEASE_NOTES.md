# AllWebPro Core 2.2.2

Core 2.2.2 repairs the inquiry-detail regression found while the Catering
module adopted the shared Core 2.2 sales workflow.

`InquiryService::find()` and the inquiry assignment selector used a nonexistent
administrator `name` column. The canonical schema stores `username`, so SQLite
raised `no such column: a.name`; MySQL and MariaDB would fail on the same
query. Both paths now select `username` with the existing display alias.

The repair changes no database structure and preserves every inquiry, note,
assignment and quote. Package ownership remains enforced when reading and
adding notes. Catering and other industry snapshots are unchanged.

Regression coverage submits an inquiry, opens its detail with no notes, adds
an internal note, reopens it with the author's username, rejects a cross-
package lookup, exercises the administrator selector, and renders the complete
detail view.

GitHub Actions run 539 (`40214953921`) passed all six jobs on source commit
`c1fe92f2df6769ea0963ffa6d45f602622cc6142`, including PHP 8.4/8.5,
Core-only boot, native MySQL/MariaDB, installer and artifact-contract checks.
