# AllWebPro Core 2.4.0

Core 2.4.0 provides the next reusable content layer for industry modules.
Modules can ship useful starter records without owning a second CMS, select
Core Media instead of hard-coded image paths, and contribute validated
Schema.org data without writing public script markup.

## Delivered

- `ModuleContext::seedContent()` inserts starter records only while the
  declared package/type partition is empty and records a durable seed marker.
- Generated content editors support `media` and `media_list` fields backed by
  public Core Media records. Saves synchronize Media usage references; edits,
  replacement, alt text and focal metadata stay Core-owned.
- `ModuleContext::structuredData()` accepts keyed providers for public
  responses. Core validates allowlisted Schema.org types and safe properties,
  bounds depth/nodes/size, removes package `@context`, encodes JSON-LD with
  markup-safe flags and combines successful contributions into one graph.
- Provider exceptions are logged and isolated. A broken contribution cannot
  break the page or suppress another module's valid schema.
- Generated content deletion now verifies that the record belongs to the
  requested package and content type.

## Compatibility

- Core version: `2.4.0`
- Module API: `1` (backward compatible additions)
- Database migration: none
- Existing content and Media records are preserved.
- Modules that do not call the new APIs behave exactly as before.

## Verification status

Focused unit coverage is included for seed-once behavior, public/private Media
validation, usage synchronization, package-scoped deletion, JSON-LD escaping,
allowlisted types and duplicate provider keys. The current continuation
container has no PHP executable, so the complete GitHub Actions matrix and
packaged-host browser acceptance remain required before this candidate is
marked CI verified.
