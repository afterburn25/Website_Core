# Website Core 2.6.0

Core 2.6.0 completes the reusable Core contracts recorded as
`CORE-REUSE-5` through `CORE-REUSE-11`. All capabilities are additive and
remain dormant until an enabled package declares or uses them. Module API v1
remains backward compatible.

## Delivered

- Reusable FAQ, gallery, testimonial, service, team and CTA page blocks.
- Manifest-level semantic constraints for named Core service contracts.
- Quote attachments, queued reminders and immutable package-rendered document
  snapshots with package ownership and integrity hashes.
- Expanded SDK scaffold and a directly installable module ZIP builder that
  refuses nested ZIP files.
- Structured service-area center/radius settings, server-side provider
  registration, normalized geocode cache, distance decisions, ambiguous and
  unavailable fallbacks, audited overrides and accessible public output.
- Module theme collections with confined layouts/assets, contrast-validated
  palettes, Core Media slots, searchable administration, draft/publish/
  rollback state and deterministic fallbacks.
- Package checkout validation with bounded context, field-scoped errors,
  manual-review and quote-only outcomes, timeout/exception isolation,
  transaction-time revalidation and immutable PII-minimized evidence.

## Data and compatibility

Migration `2026_10_25_0032` adds only Core-owned, package-partitioned workflow
tables. Disable and uninstall preserve records; explicit package purge removes
the package's quote workflow, layout state, service overrides and checkout
evidence in dependency-safe order. Geocoding provider secrets remain captured
inside server-side package closures and are never stored or rendered.

## Still external or module-owned

- Catering remains separate and was not changed by this Core release.
- Catering still must supply ten distinct layouts, ten image sets and four
  accessible palettes per layout, then adopt the forms, service-area and
  checkout hooks without losing existing records.
- Landscaping and a second independent module must prove the same contracts.
- Real provider, shared-host, root/subfolder browser, mobile, accessibility,
  performance, install/upgrade/rollback and mail-certificate acceptance remain
  release gates.
