# Website Core 2.6.2

Merged to `main` on 2026-10-26 via
[PR #8](https://github.com/afterburn25/Website_Core/pull/8).
**Commercial release not yet published:** latest main CI passed; packaged
shared-host, independent review, live licensing, and update-signing acceptance
remain open. Track evidence in `docs/2.6.2_RELEASE_READINESS.md`.

## Module administration navigation

- `ModuleContext::adminPage()` now accepts an optional fifth `icon` argument.
- `ModuleContext::adminResource()` accepts the same declaration through its
  `options.icon` value.
- Safe lowercase icon tokens are carried into Core's shared administration
  navigation instead of forcing every module destination to use the generic
  module icon.
- Existing modules remain compatible and continue to receive the `modules`
  fallback when they do not declare an icon.

## Industry theme chooser

- Module theme variants may declare a safe packaged thumbnail.
- Appearance presents visual theme cards with one color-palette dropdown and
  one Activate action per theme; activation publishes the selected layout,
  palette, and optional image overrides in one transaction.
- The previous generic layout-collection wording and multi-form
  palette grid are removed from the administrator-facing experience.

## Update and recovery safety hardening

Core 2.6.2 acceptance work also strengthens the update/rollback file writer.
It rejects linked destination paths and linked ancestors, including adjacent
directories sharing a lexical root prefix, before any deployment file is
modified. Rollback preflights all members before restoring the first file,
and both paths use newly generated temporary filenames to avoid predictable
temporary-file symlink targets. This is automated-test hardening, not a
substitute for a signed production update or actual shared-host recovery test.

## Mandatory verified rollback snapshot before Core updates

Core updates now require a successfully written and read-back-verified
rollback ZIP before replacing any deployment files. Failed backup directory
creation, source reads, archive writes, ZIP finalization, or checksum
verification stop the update without touching site files. Recovery filenames
include a random suffix to prevent same-second collisions. This does not
replace operator-led recovery testing on actual shared hosting.

## Deployment note

When module files are replaced through a hosting file manager, open
**Administration → Modules** and select **Finalize update** for that module.
This runs its pending migrations and synchronizes the database version; merely
copying a combined archive over an installed site does not perform that step.
