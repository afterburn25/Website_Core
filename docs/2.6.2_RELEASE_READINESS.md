## CI artifact handling

The `artifacts` job builds `COMPLETE-UPLOAD`, `UPDATE`,
`FULL-PROJECT`, reference packages, and their SHA-256 manifest. It already
publishes direct Catering and Landscaping test/repair artifacts. This
release-readiness change adds direct, extracted `COMPLETE-UPLOAD` and
`FULL-PROJECT` **CI acceptance downloads**: GitHub Actions creates the
one download ZIP itself, so no built ZIP is placed inside another ZIP.
Hidden protection files must be preserved.

**Do not present CI Actions downloads as a signed production release.**
An Actions download is recompressed by GitHub, so its downloaded ZIP
checksum is not the checksum of the original `/tmp/dist/*.zip` builder
artifact. For an immutable release, verify the bytes of the *published*
release assets against checksums generated for exactly those bytes.
The CI-generated `UPDATE` remains contract-tested but is not published
as a ready-to-install update until the signing/trust and hosted checks pass.

checks out the exact authoritative `Core_Mods` commit
`ecdf34b8a471f5db113a1cadc84c78fc688e735a` alongside the Core candidate.
It stages the module as a **temporary CI overlay** in `examples/industry-catering`
(without copying that module's separately published `releases/` ZIP directory),
then runs Core tests, the package builder, an explicit nested-ZIP rejection
case, a real MySQL installer/activation smoke test, and creates a directly
extractable `Catering-2.1.0-AUTHORITATIVE-TEST-BUNDLE` Actions artifact.

This integration check is intentionally separate from the historical
`examples/industry-catering` snapshot. **A passing check does not mean that
snapshot has been synchronized or that the published Core artifact now embeds
Catering 2.1.0.** For production, review and explicitly promote the tested
module snapshot, repeat exact packaged-host/browser acceptance, and verify
licensed bundle fulfillment (the CI keyless test is not a live license test).
The module pin must be updated through review for future Catering releases.


## Proposed Catering 2.1.1 snapshot promotion (review branch)

The candidate on `chatgpt/catering-21-snapshot-promotion-20261103`
replaces the historical 0.2.0 reference snapshot with **Catering 2.1.1**
from the merged authoritative `Core_Mods:module/catering` commit

assets, all migrations, theme templates, source-level acceptance tests and

This supersedes the earlier, **failed** attempted 2.1.0 promotion:
the default Heritage Editorial layout omitted header social links even with
Core `social.placement=both`, and several of the ten layouts skipped a
header or footer placement. Authoritative Core_Mods PR #2 fixed social
placement across all ten layout templates and passed its own PHP 8.4/8.5,
MySQL 8.4, MariaDB 11.4, and module CI checks before merging. Core's
reference test retains its both-placement and link-count assertions, with an
updated selector for the new theme-header-action markup.

The exact pinned authoritative integration workflow is also updated from
2.1.0 to **2.1.1**. Neither the upstream green module CI nor the earlier
2.1.0 standalone integration proves this promoted Core snapshot. **Do not
merge the promotion until all exact-head Core CI and authoritative
integration checks pass.** After merge, fresh CI artifacts must show
Catering 2.1.1; never represent older 2.1.0 artifacts as current.

Still outstanding for production: live packaged shared-host browser matrix,
rollback, actual license purchase/download/validation and signed update trust.
No production release or deployment is approved by this promotion alone.
