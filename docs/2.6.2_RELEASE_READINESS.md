## CI artifact handling

The `artifacts` job builds `COMPLETE-UPLOAD`, `UPDATE`,
`FULL-PROJECT`, reference packages, and their SHA-256 manifest. It already
publishes direct Catering and Landscaping test/repair artifacts. This
release-readiness change adds direct, extracted `COMPLETE-UPLOAD` and
`FULL-PROJECT` **CI acceptance downloads**: GitHub Actions creates the
one download ZIP itself, so no built ZIP is placed inside another ZIP.
Hidden protection files must be preserved.

**Do not present CI Actions downloads as a signed production release.**
An Actions download is recompressed by GitHub, so its downloaded ZIP
checksum is not the checksum of the original `/tmp/dist/*.zip` builder
artifact. For an immutable release, verify the bytes of the *published*
release assets against checksums generated for exactly those bytes.
The CI-generated `UPDATE` remains contract-tested but is not published
as a ready-to-install update until the signing/trust and hosted checks pass.
